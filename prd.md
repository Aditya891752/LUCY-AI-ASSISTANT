# Product Requirements Document (PRD) - Lucy (Personal Life Assistant)

## 1. Executive Summary & Vision
**Product Name:** Lucy (Personal Life Assistant)  
**Theme:** "Winter Arc" — extreme discipline, focused clarity, uncompromising tracking, and high performance heading into year-end and beyond.  
**Core Purpose:** Replace forgetful, hallucinating chatbots with a true personal memory core. Lucy stores, indexes, and queries the user's ground-truth data (profile, meetings, meals, health, workouts, supplements, habits, money). Lucy never guesses answers; every AI response is grounded in real database rows through a strict **Double Verification Pipeline**.

---

## 2. Problem Statement
- **Chatbot Amnesia:** Mainstream conversational agents (ChatGPT, Gemini, Google Assistant) suffer from context window limits, forget logged data, make subtle factual mistakes, and lack structured tracking.
- **Fragmented Life Tracking:** Users currently juggle separate apps for calendars, meal macros, workout routines, habit trackers, and personal budgets.
- **Hallucinated Recommendations:** General AI wellness tools guess user history, make up numbers, and offer unsafe or ungrounded health advice.

---

## 3. User Persona & Target Audience
- **Target User:** Driven individuals seeking deep personal discipline ("Winter Arc"), structured self-improvement, and zero-bullshit accountability across daily routines, diet, training, and finances.
- **Usage Model:** Single-user per account, mobile-first web app (PWA) with desktop parity.

---

## 4. Guiding Product Principles
1. **Own-Data First:** Lucy answers questions strictly using verified database rows. If data is missing, she explicitly says so.
2. **Double Verification Guarantee:** Every claim in an AI-generated answer or weekly plan is fact-checked by an independent verification agent against cited database rows before reaching the UI.
3. **Deterministic Math:** Aggregations, calorie balances, macro sums, and budget projections are computed in deterministic backend code, never generated by an LLM.
4. **Permanent Memory & Zero Silent Loss:** Everything logged by the user is structured, versioned, and persisted with strict Row Level Security (RLS).
5. **Safe Health Boundary:** Lucy is a personal tracking companion, not a medical professional. Lucy flags out-of-range vitals with medical disclaimers and provides no diagnostic assertions.

---

## 5. Functional Requirements & Feature Modules

### 5.1 Onboarding & Baseline Profile (Hard Gate)
- The app remains locked until profile onboarding is 100% complete.
- **Fields:**
  - Gender: `Male`, `Female`, `Other`, `Prefer not to say`.
  - Formula Baseline (if `Other`/`Prefer not to say`): Prompts explicit calculation baseline (`Male`, `Female`, `Average`) ensuring accurate metabolic math without bias.
  - Demographics: Age/DOB, Height (cm), Weight (kg), Activity Level (Sedentary, Lightly active, Moderately active, Very active, Extremely active).
  - Goals: Array selection (`fat loss`, `muscle gain`, `maintenance`, `discipline`, `savings`).
  - Diet Preferences: `veg`, `non-veg`, `vegan`, `eggetarian` + Freeform allergies list.
  - Sleep Schedule: Target wake time, sleep time, and device timezone (auto-detected, editable).
- **Derived System Baselines:**
  - BMR and TDEE via Mifflin-St Jeor formula.
  - Daily calorie target & minimum protein requirement ($g$).
  - Baseline daily water hydration target ($ml$).
  - Health vital reference bounds.

### 5.2 Omnipresent Command Bar & Quick Capture
- Single quick-entry bar accessible on every view via hotkey or thumb reach.
- Accepts natural language inputs (e.g., *"log lunch: 2 rotis and paneer burji"*, *"remind me dentist tomorrow 4pm"*, *"how much did I spend this week?"*).
- Server-side intent classifier routes text to:
  1. Meal Logging
  2. Event / Reminder Scheduling
  3. Health Metric Logging
  4. Q&A / Search Query
- **Mandatory Confirmation Card:** Before mutating database records, parsed data is presented in a structured confirmation card with an explicit "Confirm / Edit" step.

### 5.3 Meal Tracker & Macro Engine
- Natural language meal parsing via Gemini server route returning structured JSON: dish list, estimated calories, protein (g), carbs (g), fat (g).
- Client allows instant manual override of any macro; user edits permanently supersede AI estimates (`user_edited: true`).
- Real-time circular progress indicators comparing consumed vs. target calories, protein, carbs, fats, and water.
- Daily and weekly historical macro breakdowns.

### 5.4 Health & Vitals Monitoring
- Daily tracking: Weight, water intake, sleep duration, manual steps count, mood score (1 to 5).
- Optional clinical metrics: Blood pressure (systolic/diastolic), Blood glucose.
- Trend visualization over 7-day, 30-day, and 90-day intervals.
- Non-diagnostic reference checks: Flag values outside standard medical ranges with a gentle caution to consult a physician.

### 5.5 Fitness, Habits & Supplements
- **Workout Logger:** Exercise catalog, sets, repetitions, weights (kg), session duration.
- **Supplement Manager:** Daily dosage schedule, active status, timestamped one-tap completion logs.
- **Discipline & Habit Tracker:** Target completions per week, streak tracking, cumulative points system to reinforce consistency.

### 5.6 Personal Finances (Winter Arc Year-End View)
- Categorized income and expense ledger.
- Monthly budgets per category, total monthly savings goals.
- Year-end runway and projection engine.
- Bi-directional link to Winter Arc planner (diet and supplement proposals cannot exceed available grocery/wellness budget).

### 5.7 Ask-Your-Data Q&A Engine
- Natural language query interface grounded across data categories (`Schedule`, `Meals`, `Health`, `Fitness`, `Supplements`, `Habits`, `Money`, `Notes`).
- Structured tool execution (`query_meals`, `query_events`, `query_health`, `query_money`, `query_notes`).
- Returns answers annotated with a green "Verified" badge and expandable source cards containing row IDs and record dates.
- Long-term "Notes" category stores explicit user preferences and constraints (*"I practice intermittent fasting, no meals after 8 PM"*).

### 5.8 Winter Arc Weekly Planner
- One-tap weekly plan generator synthesizing: profile targets, past 2-4 weeks of logged behavior, financial constraints, and custom notes.
- Generates a holistic 7-day schedule: workout splits, daily meal targets, supplement reminders, habit targets, and a weekly checklist.
- Rendered as an interactive board with check-offs and drag-and-drop adjustments.
- Plan undergoes the exact same Double Verification and Health Safety pipeline as Q&A answers.

---

## 6. Non-Functional Requirements
- **Performance:** Sub-100ms UI interactions; optimistic updates for all check-offs and logs; skeleton loaders during data fetch.
- **Security:** Zero client-side API keys; PostgreSQL Row Level Security (RLS) on 100% of tables; server-side token validation on all endpoints.
- **Accessibility:** Full keyboard navigability, WCAG AA compliant contrast ratios, accessible form labels and aria attributes.
- **Reliability:** Graceful degradation on voice input (fallback to typed input); error boundary fallbacks for failed AI generation.
- **Offline / PWA:** Installable manifest, service worker caching shell assets, push notification subscription via VAPID Web Push.

---

## 7. Definition of Done (Release v1.0)
A user can register, complete gated onboarding, log daily life data through natural voice or text, receive web push alerts for scheduled reminders, query their past habits with verified data citations, and manage their personalized Winter Arc weekly plan on an installable web app.
